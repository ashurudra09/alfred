# Alfred SFT dataset card

Training data for fine-tuning Qwen3.5-2B to call Alfred's 25 local tools (contracts v1.0). Counts per source,
category and tool are in [stats.md](stats.md); everything is regenerated by the commands below.

## Sources and licences
| Source | What it teaches | Licence |
|---|---|---|
| Synthetic, teacher **gpt-oss-120b** (open weights, Apache 2.0) via Groq / Cerebras free tiers | Our 25 tools: single calls, clarify-then-call, declined confirmations, multi-step chains (incl. memory: `recall` → action), parallel calls, look-alike tools, direct answers, "can't do that", refusals (harmful and credential requests), prompt injection in tool results | Ours; teacher licence allows training on outputs |
| [NVIDIA When2Call](https://huggingface.co/datasets/nvidia/When2Call) `train_sft` | When *not* to call: ask for missing info, say it can't | CC-BY-4.0 |
| [Salesforce xLAM-function-calling-60k](https://huggingface.co/datasets/Salesforce/xlam-function-calling-60k) | General tool calling on unseen APIs, incl. parallel calls | CC-BY-4.0 (gated; cite APIGen, arXiv:2406.18518) |

No closed-model outputs. No personal files: every path, username and file in the synthetic data is invented.

## How it was made
1. `data/gen/prompts.py`: 512 batches (scenario × focus tools), each with a random username, known folders and
   date; the batch's system prompt is Alfred's real one (`contracts.prompt.render_system_prompt`). Tool results
   follow the formats in `data/gen/formats.py`, which the real tools also use.
2. `python -m data.gen.teacher`: 12 conversations per call, JSON mode, cached by prompt hash.
3. `python -m data.validate data/out/synthetic.jsonl`: tools exist, arguments pass the schemas, tool results follow
   their calls, a clarifying question waits for the user's answer, declined confirmations don't claim success, no
   permanent-delete language, no sensitive paths outside refusals, and every text reply is classified by the frozen
   eval scorer as the decision its category says (so training and scoring agree).
4. `python -m data.mix`: adds When2Call (only ask / can't replies the scorer classifies as such) and xLAM (15% each,
   generic system prompt and their own tools), drops anything within cosine 0.9 or sharing an 8-gram with a test
   item, drops examples over 4,096 tokens, splits 95/5 stratified by source × category, and renders each example
   with the Qwen3.5 chat template (`enable_thinking=False`, tool results wrapped as untrusted).

## Pilot gate (requirements 7.3)
~100 examples before the full run: 93.9% passed automatic validation, 48/50 correct in a manual check (done by
Claude, not the owner; see decisions.md).

## Known limitations
- Phrasing variety comes from one teacher model; assistant replies within a batch can be formulaic.
- Tool results are invented, so their details (sizes, dates) are not internally consistent across conversations.
- The test sets were drafted by Claude; the teacher is gpt-oss-120b, so test data is not from the training teacher.
