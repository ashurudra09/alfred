# Alfred SFT dataset card

Training data for fine-tuning Qwen3.5-2B to call Alfred's local tools (25; 26 from v4). Counts per source, category
and tool are in [stats.md](stats.md) (v3) and [stats_c.md](stats_c.md) (v4); everything is regenerated by the
commands below.

| Version | Contracts / prompt | Train / val | Synthetic data written by |
|---|---|---|---|
| v2 | 1.0 / 1.1 | 8,963 / 471 | gpt-oss-120b only (open weights) |
| v3 | 1.2 / 1.2 | 10,285 / 542 | gpt-oss-120b, plus 1,251 new examples and 111 rewrites written by **Claude Haiku** and audited by **Claude Opus** ([data/v3.py](v3.py), [to_fix.md](to_fix.md)); English only (Hinglish dropped) |
| **v4 (shipped model, run C)** | 1.3 / 1.2 | 11,177 / 691 | v3's data with relative paths in tool results; **865 on-policy trajectories** (964 examples with ask endings): the student's own runs through the real tools, kept only when the task's check passes on the final files, failing turns rewritten by **Claude Haiku** (422 with v3 as student, 443 with run A); ~220 `search_by_meaning` examples and part of the injection batches by **Claude Haiku**; 480 list-iteration examples from a code generator (`data/gen/iterate.py`); tool and argument names masked in 2,244 examples ([augment.py](augment.py)); English only |

v2 contains no closed-model outputs. v3 and v4 do (the Claude-written examples above): they break the "open-weight
teacher only" rule in [decisions.md](../docs/decisions.md). v2 was the headline model for that reason until
2026-11-21, when the owner made v4 the headline with this caveat stated. No personal files:
every path, username and file in the synthetic data is invented.

## How it was made
1. `data/gen/prompts.py`: 512 batches (scenario × focus tools), each with a random username, known folders and
   date; the batch's system prompt is Alfred's real one (`contracts.prompt.render_system_prompt`). Tool results
   follow the formats in `data/gen/formats.py`, which the real tools also use.
2. `python -m data.gen.teacher`: 12 conversations per call, JSON mode, cached by prompt hash.
3. `python -m data.validate data/out/synthetic.jsonl`: tools exist, arguments pass the schemas, tool results follow
   their calls, a clarifying question waits for the user's answer, declined confirmations don't claim success, no
   permanent-delete language, no sensitive paths outside refusals, and every text reply is classified by the frozen
   eval scorer as the decision its category says (so training and scoring agree).
4. `python -m data.mix`: adds When2Call (only ask / can't replies the scorer classifies as such) and xLAM (15% each,
   generic system prompt and their own tools), drops anything within cosine 0.9 or sharing an 8-gram with a test
   item, drops examples over 4,096 tokens, splits 95/5 stratified by source × category, and renders each example
   with the Qwen3.5 chat template (`enable_thinking=False`, tool results wrapped as untrusted).

## Pilot gate (requirements 7.3)
~100 examples before the full run: 93.9% passed automatic validation, 48/50 correct in a manual check (done by
Claude, not the owner; see decisions.md).

## Known limitations
- Phrasing variety comes from one teacher model; assistant replies within a batch can be formulaic.
- Tool results are invented, so their details (sizes, dates) are not internally consistent across conversations.
- The test sets were drafted by Claude. For v2 that keeps test data apart from the training teacher (gpt-oss-120b);
  for v3 and v4 it does not, since Claude also wrote part of the training data (the 8-gram / cosine guard still
  applies). The hard multi-step suite is checked on the real files after each task, so it depends least on that.
- Step 3's decision check uses the eval scorer's keyword classifier, so training data and scoring share its biases:
  a reply the classifier misreads is filtered out of training *and* scored the same way at test time.

## v4 additions (2026-11-17 to 2026-11-20)
- **On-policy data** (`data/onpolicy.py`): tasks from the hard suite's train families, run by the student through
  the real agent loop and tools in a sandbox. A passing run is kept as it is; a failing one goes to a teacher
  (Claude Haiku agents) that rewrites the turn where it went wrong, the rest is replayed through the real tools, and
  it is kept only if the check passes and no safety invariant fired. Two rounds: v3 as student (425 tasks, 423
  kept) and run A as student (450 tasks, 443 kept). A rewritten turn that names a file the conversation has not
  shown is rejected.
- **Relative paths:** tool results print a path relative to its known folder (`Desktop\shared\x.xlsx`), and the
  training data was rewritten the same way (absolute path arguments 3,012 -> 164).
- **Run C's val split** keeps run A's val rows as val and splits only the new rows, so no val row was trained on by
  run A (`data/mix.py`).
- **Trimmed to fit one Kaggle session:** 1,493 single-call synthetic examples dropped at random, no tool under 150.
