# v3 change plan: folder-less search, system prompt, v2 format cleanup

Three changes before the v3 training run, in this order (the data steps depend on the tool change). Everything data-side
is a scripted pass inside `python -m data.v3 assemble`, so it reruns from `v3/v2.valid.jsonl` and the audited files:
nothing is regenerated by hand. Status of the data before this plan: [to_fix.md](to_fix.md) (top) and
`data/out/v3/*.audit.md`.

## A. Tool change: `search_files` without a folder (issues 005, 009, 014)

**Why:** with `folder` required, "where is budget.xlsx?" has no right single call. The v3 data works around it by
calling `search_files` once per known folder in one message: **75 such messages** (009b 45, 009a 18, 007 8, 005 2,
013b 2), 6-7 calls each. The regression items already expect the folder-less form (`regress-009-where-is`,
`-which-resume`, `-open-parent`, `-chain-find` expect `{"query": ...}` only). In-domain items all name a folder, so
they are unaffected.

**Code**
1. `src/alfred/contracts/tools.py`: `folder: Annotated[str | None, Field(description="Leave out to search all known
   folders")] = None`; docstring adds "`query='*'` matches every name; results newest first".
2. `src/alfred/tools/files.py` `search_files`: roots = `[resolve_safe(folder)]` if a folder is given, else the known
   folders (`known_folders().values()`, not Alfred's home), skipping a root that sits inside another. One shared
   `max_scan` budget across roots, so a folder-less search costs what one big folder does
   (`# ponytail:` note: shared budget, per-root budgets if results come back thin).
3. Regenerate `tools.json` (`uv run python -m alfred.contracts.export`). Contracts stay **1.1**: 1.1 was never
   trained or released (decision below).
4. `data/gen/prompts.py` `HINTS["search_files"]`: leave out `folder` when the user names none (for future teacher runs).
5. Test in `tests/tools/test_tools.py`: two known folders, a file in each, a folder-less search finds both, newest first.

**Data (scripted, `data/v3.py`)**
- **T1, merge fan-outs:** an assistant message with ≥ 2 `search_files` calls that share query/extension/days and
  cover all of the system prompt's known folders, where no user turn names a folder, becomes one call without
  `folder`. Its results merge: hit lines pooled, sorted by modified date (newest first), header recounted
  ("N files:"); all misses → `No matching files found.` Searches over 2 folders the user named (007's "largest pdf in
  downloads and documents") stay as they are.
- **T2, unasked folders in v2:** a v2 example's first `search_files` whose folder isn't named in any user turn (name,
  alias such as "docs", or path) loses its `folder` argument (~30 per the 009 audit). The result stays the same.
- Replies that say "I searched Documents, Downloads, …" stay true; leave them.

## B. System prompt change (issues 001, 010, 009, 013, 017)

**Code:** `src/alfred/contracts/prompt.py`, replace the rule

> Changes to files run only after the user confirms them in the app, so call the tool directly. Deleting always means move_to_recycle_bin.

with

> When the user asks for a change, call the tool directly: the app asks them to confirm. Don't change anything they didn't ask for. Deleting always means move_to_recycle_bin.
> Look things up before using them: never guess a file name, a number or a date.

The app (`agent/loop.py`) and the eval both render the prompt from here, so they pick it up.

**Data:** in `assemble`, swap the old line for the new two in every synthetic system message. All synthetic examples
were rendered from this template, so assert that every one contains the old line exactly and fail loudly if not.
When2Call/xLAM rows are left as they are (they have their own prompts). Cost: about +30 tokens per example; max is
3,931 of 4,096 today, so check the "longer than 4096" count after `data.mix`.

## C. v2 format cleanup (361 of 6,250 v2-derived examples)

Found by a scan of tool results against what the real tools print. Each fix is a rule in `assemble`. "Drop" means
drop the example; afterwards check the per-tool counts.

| Pattern | Examples | Fix |
|---|---|---|
| Placeholder lines (`...`, `2. ...`) in results | 88 | Remove the line. Where a header count ("3 files:") no longer matches the lines left: if the reply states that count, drop; else recount the header. |
| KB with decimals (`1.2 KB`; the tool prints whole KB) | 55 | Round to whole KB in the result, and replace the same string in the replies. |
| Dates after the example's "today" (search modified dates, note dates, recall "saved" dates) | 205 | Shift every such date in the example back by one offset, so the newest is ≤ today (order and gaps kept, replies updated too). Drop where a reply uses relative day words (today/yesterday/last week/N days ago). |
| `disk_usage` in a made-up format | 30 | Drop. |

Then: if a tool falls under 200 in train (`network_status` is at 199 now), one small Haiku → Opus top-up, as before.

## Checks, in order
1. Code: `uv run pytest -q` (141 tests plus the new one).
2. `assemble`: print counts per transform (merged / unfoldered / prompt-swapped / cleaned / dropped), then run
   `data.validate.check` on every example (0 errors).
3. Rerun the scan (all four patterns → 0) and a T1/T2 check: no message has > 1 `search_files` over all known folders.
4. Opus audit of a random sample: 40 transformed examples (T1, T2, cleanup), same AUDIT.md checklist.
5. `uv run python -m data.mix`, then `uv run python -m data.dedup --check` (0 near-duplicates), and stats.md: every
   tool ≥ 200, 0 dropped as too long.
6. Update to_fix.md (tool-update table: `search_files` folder done; system prompt done) and patch_notes v3.
